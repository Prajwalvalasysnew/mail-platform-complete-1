# Open & click tracking

The platform can track whether recipients open your emails and which links they click. Tracking is **opt-in per message** and is off by default.

---

## Enabling tracking

Set `tracking_opens` and/or `tracking_clicks` on a send:

```bash
curl -X POST https://api.mailplatform.example/v1/send \
  -H "Authorization: Bearer $MAILPLATFORM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "hello@mail.yourcompany.com",
    "to": "alice@example.com",
    "subject": "Your weekly update",
    "html": "<p>Here are this week'\''s highlights.</p>",
    "tracking_opens": true,
    "tracking_clicks": true
  }'
```

| Option | What it does |
|---|---|
| `tracking_opens` | Injects a 1×1 invisible pixel at the end of the `<body>`. When the image loads, an `opened` event is recorded. |
| `tracking_clicks` | Rewrites all `https://` and `http://` links in `html` through a redirect URL. When the recipient clicks, a `clicked` event is recorded before the redirect. |

Tracking requires an HTML body (`html`). Plain-text (`text`-only) messages cannot be tracked.

---

## Receiving tracking events

Subscribe to `opened` and `clicked` event types on your webhook endpoint:

```bash
curl -X POST https://api.mailplatform.example/v1/webhooks \
  -H "Authorization: Bearer $MAILPLATFORM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourapp.example.com/hooks/mail",
    "events": ["opened", "clicked"]
  }'
```

**`opened` payload**
```json
{
  "message_id": "msg_abc@mail.yourcompany.com",
  "event_type": "opened",
  "occurred_at": "2026-06-09T14:22:00.000Z",
  "verdict": "human",
  "ip": "203.0.113.45",
  "user_agent": "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) ..."
}
```

**`clicked` payload**
```json
{
  "message_id": "msg_abc@mail.yourcompany.com",
  "event_type": "clicked",
  "occurred_at": "2026-06-09T14:22:05.000Z",
  "url": "https://yourcompany.com/blog/post-1",
  "verdict": "human",
  "ip": "203.0.113.45",
  "user_agent": "Mozilla/5.0 ..."
}
```

The `verdict` field tells you whether the event was generated by a real human or an automated system (see bot detection below).

## Bot detection

Many email clients, security gateways, and link-scanning tools automatically fetch tracking pixels and follow links when they receive an email — before a human ever reads it. Without bot detection, these automated fetches inflate your open and click rates.

The platform applies multi-signal bot detection and sets a `verdict` on every tracking event:

| Verdict | Meaning |
|---|---|
| `human` | Strong signals indicate a real user. Safe to act on. |
| `bot` | Definitively automated (Apple MPP, known scanner UA, datacenter IP). Do not treat as engagement. |
| `suspicious` | Ambiguous signals. Use with caution. |

**Signals used:**

- **Apple Mail Privacy Protection (MPP)** — Apple pre-fetches pixels via a proxy immediately on delivery, before the user opens the email. Detected by the MPP user agent header.
- **Security gateway fingerprints** — known crawlers, link-scanners, and anti-phishing bots operated by enterprises and ISPs.
- **Timing** — opens or clicks occurring in under 1 second of delivery are almost certainly automated.
- **Click without prior human open** — a click event that has no preceding `human` open on the same message is flagged as suspicious.
- **Datacenter IP ranges** — opens/clicks from cloud or datacenter IP blocks with no browser-like UA.

### Using verdicts in your application

```ts
app.post('/hooks/mail', (req, res) => {
  const event = req.body;

  if (event.event_type === 'opened' || event.event_type === 'clicked') {
    if (event.verdict === 'human') {
      // Safe: real engagement — update your CRM, trigger follow-up
      markRecipientAsEngaged(event.message_id, event.event_type);
    } else if (event.verdict === 'bot') {
      // Ignore — automated probe, not real user interest
    } else {
      // 'suspicious' — log but don't trigger high-stakes automations
      logSuspiciousEngagement(event);
    }
  }
  res.sendStatus(200);
});
```

Use `human_opened_at` and `human_clicked_at` on message records (via `GET /v1/messages/:id`) to access the timestamp of the first confirmed-human engagement event.

## Privacy considerations

Open tracking uses a pixel image and click tracking uses redirects — both are standard, widely used techniques. However:

- **EU/GDPR:** If you are targeting EU recipients, disclosure of tracking in your privacy policy is strongly recommended. Some email service providers include a consent toggle for tracking.
- **Unsubscribe pages:** When a recipient clicks "Unsubscribe", that click is recorded but suppression is handled regardless of the tracking verdict.
- **Apple Mail Privacy Protection:** Since iOS 15 and macOS Monterey, Apple Mail pre-loads all remote images through Apple's privacy proxy. Open rates for Apple Mail users are unreliable — consider click rate as a more reliable engagement metric for this audience.

## How click rewriting works

When `tracking_clicks` is enabled, the worker rewrites each unique `https://` or `http://` link in the HTML body to a redirect URL:

```
Original:  https://yourcompany.com/blog/post-1
Rewritten: https://track.yourplatform.example/c/enc_msg_id/link_id
```

When the recipient clicks, the tracker:
1. Records the `clicked` event (with bot detection).
2. Immediately redirects (HTTP 302) to the original URL.

The redirect is transparent to the recipient and takes under 50 ms in most regions.

**What is and isn't rewritten:**
- `https://` and `http://` links in `<a href="...">` tags are rewritten.
- `mailto:`, `tel:`, fragment anchors (`#section`), and the unsubscribe URL are never rewritten.
- If `tracking_clicks` is off, links are delivered as-is.
