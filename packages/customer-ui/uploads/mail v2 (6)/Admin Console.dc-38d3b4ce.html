How the DLQ works

BullMQ moves a job to the dead-letter queue after it exhausts its retry backoff schedule. Each queue (send, webhooks, events) has a separate DLQ. Replay calls POST /admin/dlq/:id/replay and re-enqueues the job with its original data. Purge all requires { "confirm": true } in the request body as a safeguard.
